## 三、修复的 BUG 清单

| # | 问题 | 原因 | 修复 |
|---|---|---|---|
| 1 | 登录接口 500 | 静态接口方法 `toUserVO()` 被实现类无限定调用（Java 不继承接口静态方法）；IDE 编译产物掩盖了 javac 错误 | 改为 `UserService.toUserVO()` 全限定调用，并改用 `mvn clean package` 全量编译 |
| 2 | 编译失败：PaginationInnerInterceptor 找不到 | MyBatis-Plus 3.5.9+ 分页插件拆分至独立模块 | pom 增加 `mybatis-plus-jsqlparser` 依赖 |
| 3 | 日志查询 500 | `LambdaQueryWrapper.ge(condition, col, parseStart(null))` 条件为 false 时参数仍被求值 | 参数表达式加空值保护 |
| 4 | 7 天趋势 500 | `GROUP BY DATE(create_time)` 与 `SELECT DATE_FORMAT(...)` 不兼容 only_full_group_by | GROUP BY 与 SELECT 使用同一表达式 |
| 5 | 后端启动端口占用 | 开发期 mvn spring-boot:run 的 fork 进程残留 | 改用 jar 方式运行，kill 残留进程 |

## 四、兼容性测试

- **桌面端**：Chrome、Edge 最新版，1440/1024 宽度下布局正常，管理端表格自适应。
- **平板端**：768 宽度下管理端侧边栏收起为抽屉菜单，内容区单列。
- **手机端**：375 宽度下顶部导航收起为汉堡菜单 + 侧滑抽屉，卡片列表单列，表单纵向排列，表格横向滚动，无横向溢出滚动条。
- **真机测试**：手机与电脑同一局域网，访问 `http://<电脑IP>:5173`，走通登录→发帖→浏览→点赞→评论全流程，捐助弹窗正常。
- **构建兼容**：`mvn clean package -DskipTests` 产出可运行 jar；`npm run build` 2315 模块构建成功。

## 五、结论

系统全部核心功能模块联调通过，权限控制、事务一致性、异常拦截、日志脱敏等非功能需求验证合格；测试中发现 5 个 BUG 均已修复并回归通过，平台可投入演示使用。
